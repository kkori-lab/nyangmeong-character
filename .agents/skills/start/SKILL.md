# 세션 시작

`<이름>`은 브랜치 이름이다(`/`가 있으면 앞부분). 고르기와 기획은 한 턴에 끝낸다. 그래야 이 스킬의 모델(Opus)로 기획한다.

1. `sh scripts/start-check.sh $ARGUMENTS`를 실행한다. 브랜치 확인, 원격 합치기(`docs/convention/git.md`), 설정 키 점검, 검증 루프 보관, 핸드오프 생성, 작업 후보 찾기를 스크립트가 한다. 이 일을 손으로 다시 하지 않는다. 종료 코드가 0이 아니면 출력을 그대로 보여 주고 멈춘다.
   - "원격"에 합친 커밋이 있으면 보고 맨 앞에 커밋 수와 눈에 띄는 변화(다른 사람이 끝낸 마일스톤, 새 모듈, `deploy/`·`.github/` 변경)를 한두 줄로 적는다.
   - "검증 루프"가 `보관`이면 기획을 새로 쓰지 않고 그 마일스톤을 이어 간다. 보고 맨 위에 "검증 루프가 <N>회차 실패로 보관돼 있어 이어 갑니다. 기획과 기준 파일은 그대로입니다. 루프를 버리고 새로 기획하려면 `! sh scripts/verify-loop.sh clear` 후 `/start`를 다시 실행하세요"라고 적고, 6번의 `승인` 없이 `/impl`로 이어 가라고 안내한다.
   - 핸드오프는 출력의 "지금 하는 것"과 "다음에 할 것 맨 위"로 본다. 파일 전체를 읽지 않는다.
   - PR 병합 여부는 출력의 "PR"로 본다(`gh`를 따로 부르지 않는다).
2. 작업을 고른다. 사람에게 묻지 않는다.
   - 인자가 있으면 출력에 나온 그 마일스톤.
   - 인자가 없으면 "다음에 할 것 맨 위", 그것도 비면 "대기 맨 위". "기다리는 것"은 고르는 조건이 아니다.
   - "마일스톤 파일이 없거나 형식이 다릅니다"이면 `docs/convention/milestone.md` 절차로 새로 만든다. git 이력에서 되살리지 않는다.
3. "기획 상태: 승인 전"이면 이전 기획을 지우고 그 마일스톤을 `sh scripts/milestone-status.sh <M번호> 대기`로 되돌린다(고른 작업과 같으면 지우지 않고 고쳐 쓴다). 고른 작업과 시작 시각을 `<작업> — 기획 (시작 <YYYY-MM-DD HH:MM>)` 형식의 첫 줄로 적고, `sh scripts/milestone-status.sh <M번호> 진행`을 돌린다.
4. 기획을 "지금 하는 것" 아래에 먼저 쓴다(끊겨도 `/verify`가 읽을 수 있게).
   - 기준은 문서가 아니라 원본 Python 코드다. 마일스톤의 `원본:` 파일에서 `기능:`에 적힌 함수·경로를 검색해 그 함수와 그것이 부르는 것만 읽는다(파일 전체를 읽지 않는다). 원본 저장소는 `../ai`·`../nyangmeong-ai` 또는 `AI_REPO`. 원본 위치를 `파일:함수`로 적고, 기획 시점의 원본 커밋(`git -C <원본> log -1 --format=%h`)을 첫 줄 아래에 `원본 커밋: <해시>`로 적는다.
   - 기능(함수·경로)마다 한 줄: 바꿀 러스트 파일, 원본 위치, 완료 조건(`명령:` 검증 명령·정답 비교 테스트, `화면:` curl로 확인할 동작). 같은 입력에 같은 출력인지 확인하는 방법(정답 파일 비교, 대조 사례 추가)을 완료 조건에 넣는다.
   - 원본과 다르게 할 수밖에 없는 것(메모리를 줄이려는 자료형 변경 등)은 그 줄에 `차이:`와 이유를 적고, 결과(픽셀·바이트)는 같게 둔다. 결과까지 달라지면 `docs/design/migration.md` "알려진 차이"를 고치는 것을 기획 항목으로 넣는다.
   - 2번 서버나 Java가 필요한 확인은 `화면:`에 사람이 할 명령과 기대 결과로 적는다(이 PC에서 서버 SSH를 하지 않는다).
   - 아직 없는 남의 것(Java API·시크릿)은 "가짜로 먼저 만들고 나중에 연결"과 가짜를 둘 곳을 적는다. 연결은 "다음에 할 것"에 남긴다.
   - 정할 것이 있으면 `질문:` 줄에 선택지와 추천안을 적는다(`/impl`이 답을 받기 전에는 구현하지 않는다).
   - 맨 아래 `새 의존성:` 줄. 추가할 크레이트·버전·이유, 없으면 `없음`.
5. 보고하고 멈춘다. 순서:
   - "설정 키"에 빠진 키가 있으면 맨 앞에 그 줄을 그대로.
   - 마일스톤 파일을 이번에 만들었으면 목록(M번호·제목·상태).
   - 기획. 새 의존성·질문이 있으면 따로 눈에 띄게.
   - 끝에: "기획대로 가려면 `승인`(또는 `/impl`), 고칠 점은 그 내용을 답해 주세요. 다른 마일스톤은 `/start M4`처럼 다시 실행하세요."
6. 승인 전에는 코드를 쓰지 않는다. 고칠 점을 받으면 기획을 고쳐 5대로 다시 보고한다. `승인`이라고 답하면 `impl` 스킬을 부른다. 이 스킬에서 직접 구현하지 않는다.

핸드오프는 공개 저장소에 커밋된다. 비밀값과 개인 PC 경로를 적지 않는다.
