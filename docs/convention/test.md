# 테스트

테스트를 쓰거나, 검증 명령에서 테스트가 실패했을 때 연다.

- 테스트를 지우거나 끄거나(`#[ignore]`) 기대값을 바꿔서 통과시키지 않는다. 가끔 실패하는 테스트도 꺼서 넘기지 않고 원인을 고친다. 대조 사례(`contract/compare.py`의 `CASES`)도 같다.
- PR은 `sh scripts/check.sh`가 통과해야 병합한다. CI(`.github/workflows/build.yml`)는 대조 테스트를 뺀 cargo 검사만 돈다.
- 옮긴 함수는 **원본과 같은 출력**을 테스트로 보인다. 기대값은 손으로 쓰지 않고 원본에서 가져온다.
  - 응답(상태 코드·헤더·본문): `contract/compare.py`에 사례를 더한다. Java는 `contract/fake_java.py`가 대신한다. 핸들러까지 가는 사례는 가짜 Java에 필요한 경로를 더한다.
  - 이미지 계산: 원본 Python으로 만든 정답 PNG와 픽셀 단위로 비교하는 통합 테스트를 `tests/`에 둔다. 정답 파일(캐릭터 시트 등)은 저장소에 커밋하지 않는다 — 실제 반려동물·회원 캐릭터에서 나온 그림이다. 정답 폴더 위치는 환경변수로 받고, 없으면 그 테스트는 무엇이 없어 건너뛰는지 출력한다(정답이 있는 PC의 `check.sh`에서는 반드시 돈다).
  - 값 변환 규칙(pydantic·Python 내장 함수): 원본 가상환경에서 직접 돌려 본 결과를 표로 옮기고, 확인한 날짜와 버전을 주석으로 적는다(`src/pyval.rs` 참고).
- 단위 테스트는 그 모듈 아래 `#[cfg(test)] mod tests`에, 여러 모듈을 거치는 테스트는 `tests/`에 둔다. 검증 루프는 `tests/`·`contract/`를 잠근다(`src` 안 단위 테스트는 파일째 잠글 수 없다). 기준이 되는 비교 테스트는 `tests/`에 둔다.
- 외부 AI API(OpenAI)를 부르지 않는다. 키가 없는 CI에서도 통과해야 한다.
- 각자 PC의 `.env.local`과 관계없이 돌도록, 설정이 필요한 테스트는 `Settings::from_lookup`으로 값을 넣는다.
