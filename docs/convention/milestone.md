# 마일스톤

마일스톤을 만들거나 고칠 때 연다. 프론트·백엔드·AI 저장소는 화면 ID(`SCR-…`)로 마일스톤을 나누지만, 이 저장소는 Python에서 옮기는 **이전 단계**로 나눈다. 그래서 ID는 `M<번호>`다(`scripts/start-check.sh`·`milestone-status.sh`가 이 형식을 읽는다).

## 형식

`milestones/<이니셜>.md`. 공개 저장소이므로 비밀값과 개인 PC 경로를 쓰지 않는다.

```
# <이니셜> 마일스톤

기준: `nyangmeong-ai` develop `app/character/`·`app/core/` (<확인한 날짜>)

## M3 이미지 계산 (stand_front_cut·place·…) — 대기
- 기능: <옮길 함수·경로, 쉼표로>
- 원본: <nyangmeong-ai 파일 경로>
- 기다리는 것: <남의 것·시크릿·정답 파일> (없으면 줄을 뺀다)
- 완료 조건: 명령: <검증 명령·테스트> / 화면: <curl·2번 서버에서 확인할 동작>
- 연결 남음: <기능> (<기다리는 것>, <담당>)   ← /end가 끝으로 판정할 때 남긴다
```

- 제목 끝 상태는 `— 대기`·`— 진행`·`— 끝` 셋 중 하나다. 손으로 고치지 않고 `/start`·`/end`가 `sh scripts/milestone-status.sh <M번호> <상태>`로 바꾼다.
- 순서는 앞 단계가 뒤 단계의 기반이 되게 둔다(공통 계약 → 계산 → 외부 연결과 큐 → 전환). 기다리는 것이 있어도 빼지 않고 적어 둔다.
- 마일스톤 하나는 PR 하나로 끝날 크기로 둔다. 너무 크면 `M3a`처럼 나누지 않고 번호를 새로 매겨 뒤로 민다(스크립트는 `M<숫자>`만 읽는다).

## 만들기·다시 만들기

1. 배경과 범위는 `docs/design/migration.md` "옮길 범위"를 따른다. 원본 `app/character/`의 경로·함수가 빠짐없이 어느 마일스톤의 `기능:`에 들어가야 한다.
2. 원본이 바뀌었으면(`nyangmeong-ai` develop에 `app/character/`·`app/core/` 변경) `기준:` 날짜를 고치고, 바뀐 함수가 든 마일스톤을 확인한다. 이미 `끝`인 마일스톤이면 다시 옮기는 일을 새 마일스톤으로 추가한다.
3. `/start`가 부른 경우에는 멈추지 않고 `/start`의 다음 단계로 이어 간다.
